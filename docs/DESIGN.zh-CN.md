## 1. 建议采用什么结构

先维护一个仓库 `adp-matlab`，内部使用 MATLAB `+adp` 命名空间；每篇论文只保留自己的模型、配置、特殊算法与结果清单。等某部分有独立维护者、依赖或发布周期，再拆分仓库。

交付包中的公共库仍是最小参考实现；七个论文复现包提供具有独立数学契约的具体方法。完整模块体系继续作为后续开发规范。`registry/modules.json` 明确区分 `implemented_reference` 和 `planned`，不能根据目录或设计文档判断某算法已经实现。

长期结构由三部分组成：

1. **共用算法库**：模型接口、特征、Bellman 数据、学习器、策略、约束、执行器和诊断。
2. **论文复现包**：固定论文版本与上游 commit，保存该论文的假设、参数、场景、基线、运行说明和原始结果索引。
3. **skills**：指导以后怎样开发、复现、检查和扩展前两部分。数值公式与可执行验证留在代码里，skills 负责工作流程和判断规则。

这样，每新增一篇论文通常增加一份配置、一个方法实现和必要的新模型；无需复制整套仿真、绘图、数据保存代码。

## 5. 模块责任和验收边界

| 模块组 | 输入 → 输出 | 必须回答的问题 | 第一批检查 |
|---|---|---|---|
| 问题与模型 | 状态、输入、参数 → 导数/下一状态、观测 | CT/DT？仿射/非仿射？哪些量只供仿真器使用？ | 维度、单位、平衡点、已知解析轨迹 |
| 代价与策略 | 状态/参考 → 代价；学习状态 → 输入 | 代价是否含 1/2？输入约束如何进入最优性？ | 代价非负、策略符号、LQR 对照 |
| 特征与估计 | 学习坐标 → 特征/梯度；数据 → 模型估计 | 特征作用于 x、e 还是变换坐标？ | 有限差分梯度、维度、估计误差分离 |
| 数据与学习 | 已完成样本/窗口 → 新学习状态与诊断 | on/off-policy？需要哪些模型知识？数据是否满秩？ | 解析算例、秩不足拒绝、旧策略/新策略时序 |
| 约束与证书 | 候选输入、状态、证书 → 最终候选/失败 | 名义输入变动以后，学习式和证书是否仍成立？ | 约束余量、后验可行性、失败分支 |
| 时钟与执行 | 多个输入阶段 → 施加输入与轨迹 | 学习、控制、积分何时发生？采样保持还是连续反馈？ | 保持行为、事件顺序、步长/容差敏感性 |
| 实验与记录 | 冻结配置、随机流 → 可追踪的 run | 训练/评估是否分开？是否包含失败样本？ | 重复运行、清单校验、输出防覆盖 |
| 复现与图表 | 原始数据、协议 → 指标/图/比较 | 与哪篇论文哪个版本、哪个 figure 对应？ | 配置一致、数据可追踪、全轨迹计算指标 |

函数加显式 `struct` 足以作为起点；只有真正需要可变生命周期、资源或多态时引入类。不要先建立万能 `ADPController` 类，再把所有论文方法塞入条件分支。

## 6. 必须固定的数学约定

### 状态、维度与代价

- 单个状态 `x` 为 `nx×1`，输入 `u` 为 `nu×1`；公共库保存的轨迹按样本存行：`x` 为 `N×nx`。论文包保留其原生布局；批量特征或轨迹若使用列样本，函数必须明确说明，不能靠转置猜测。
- CT：`xdot=f(x)+g(x)u`；DT：`x_next=F(x,u)`。非仿射系统直接提供 `F`/`flow`，不能假装具有一个固定的 `g`。
- 默认例子使用 `ell=x'*Q*x+u'*R*u`，不含 `1/2`。在无约束 CT 仿射二次输入代价下，`u*=-0.5*(R\(g'*gradV))`；若 `V=x'*P*x`，得到 `u*=-(R\(g'*P*x))`。输入约束、非仿射、不同成本必须重新推导，不能复用此式。
- `stage_cost` 表示瞬时代价，`cost_integral` 表示时间积分，`bellman_residual` 表示对应 Bellman 恒等式的残差。这三个名字不互换。
- `e=x-x_ref` 及 PPC/时变变换均需明确参考动态；计算价值梯度、系统导数和 `V_t` 时应用完整链式法则。

### Bellman 恒等式

默认无折扣 CT 策略评估：`delta_CT = ell(x,u_pi) + gradV' * flow(x,u_pi)`。有限时域或显式时变价值还要加 `V_t`；连续折扣率 `rho` 时减 `rho*V`。

默认 CT on-policy 积分残差：

```text
delta_IRL = V(x(t+T)) - V(x(t)) + integral_t^(t+T) ell(x(s),u_pi(s)) ds
```

固定策略下，收集 `Phi=phi(x(t))-phi(x(t+T))`，解 `Phi*w = integral(ell)`。若行为输入不同于目标策略，必须根据模型知识和论文推导建立 correction 项；不能仅将 `u_applied` 换成 `u_nominal` 后继续称为 on-policy。改变折扣、有限时域或时间变换时，也必须重新写恒等式。

DT：`delta_DT = ell(x_k,u_k) + gamma*V(x_{k+1}) - V(x_k)`；当 `ell` 已是每步成本时，不再自动乘 `dt`。CT 离散实现究竟使用连续积分还是近似求和，需要在配置和结果中记录。

### 并发学习与时间收敛

- 历史数据集保存采样时间、状态/回归量、目标、使用输入、窗口、筛选/替换规则和版本。仅有当前样本不自动构成充分历史激励。
- 同时记录回归矩阵奇异值、秩、阈值、缩放方式；只检查样本数量或矩阵范数不够。秩/正定 Gramian 的数值证据不是全域或持续激励证明。
- 对 FxT/finite-time/prescribed-time 单独标注收敛对象：状态、跟踪误差、参数误差、Bellman 残差，还是某邻域。若初值不可行、时间变量逼近奇点或秩条件失效，不能继续套用原时间界。
- `t_converged` 使用显式阈值、保持时长和首次进入/最终停留定义；有限组仿真不能验证与所有初值无关的固定时间性质。

## 7. 输入执行链与学习时间线

```mermaid
flowchart LR
  O[观测/估计状态] --> P[冻结当前学习状态生成策略]
  P --> N[u_nominal]
  N --> E[探索或人机混合]
  E --> B[u_behavior]
  B --> F[约束修正]
  F --> C[u_filtered]
  C --> A[通信、保持、限幅、执行器]
  A --> U[u_applied]
  U --> M[系统推进]
  M --> D[完成的轨迹窗口与实际输入]
  D --> L[学习更新]
  L --> P
```

这是默认组合顺序；涉及安全探索、网络接收或多参与者耦合的论文可以定义不同顺序，但必须把顺序保存在方法说明中。记录实际输入不意味着原学习定理自动适用于它。

采样实现的因果顺序：观测 → 使用旧权重计算命令 → 完成执行和积分 → 写入样本 → 更新权重 → 下一控制时刻使用新权重。若理论使用连续权重微分方程，应把权重作为增广状态积分，不在 ODE 右端依靠全局数组改变隐藏状态。

ODE 右端允许在同一时间多次求值以及拒绝步；学习计数、历史栈替换、随机数消耗和日志追加应在明确的采样/接受点发生。事件驱动系统使用显式事件与 reset map。连续反馈与零阶保持是不同的实验配置，改变求解器不等于改变控制采样周期。

最小输入字段：`u_nominal, u_behavior, u_filtered, u_applied`。没有探索或约束时字段可以相等，并记录相等的原因。网络扩展增加 `u_transmitted, u_received`；多参与者保留各自输入和实际合成输入。

## 8. 安全控制的接入方式

1. **代价/学习中加入惩罚**：记录惩罚项和约束违例；仅凭高惩罚或轨迹未越界不能宣称不变性。
2. **坐标变换/PPC/barrier value**：核对可行初值、变换定义域、逆变换、时变项和输入可实现性；不可用无说明的 clipping 躲避奇点。
3. **策略外约束过滤/优化**：独立记录优化求解状态、约束残差、slack 和最终执行输入，显式处理不可行或超时。求解器返回 success 与满足安全证书是不同检查。

4. **直接约束策略与学习证书**：性能critic、Lyapunov/Barrier证书和备用策略分别建模；记录约束是在样本、期望还是整个区域上成立。
5. **受约束HJB/可达性后端**：使用相应变分不等式、终端条件与定义域；概率校准和确定性验证分别登记。

后加的限幅、时延、共享权限、探索或执行器模型都可能改变保证，需要重新检查证书以及 Bellman 数据与策略的对应关系。保存真实失败原因；不能以 `u=0` 作为普遍安全的默认动作。

## 9. 实验、数据和论文复现规范

一次实验使用一份冻结的可序列化配置和唯一目录，包含：

```text
config.json             数值参数、模型、方法、时钟、种子与容差
result.mat              原始轨迹、权重、回归数据和诊断
summary.json            有限实验指标与状态
manifest.json           源码/配置/数据 hash、MATLAB/工具箱/平台
figures/                从 result 重建的图（需要时生成）
```

不要从 MAT 文件导入整个工作区；使用 `S=load(path,'result')`。配置中不包含函数句柄，使用可解析的注册名称；内存中的 problem/policy 可以使用函数句柄。保存 `rng` 类型/种子/状态；噪声与探索优先预生成或使用独立随机流，避免求解器调用次数改变实验。

训练与评估使用不同初值/扰动场景；评估明确冻结学习还是在线继续学习。比较方法使用相同模型、输入限制、时钟、成本和预算；给每个方法合理而可追踪的调参预算。报告所有预先列出的场景与失败，不只选择漂亮轨迹。

指标按任务选取：跟踪误差、累计成本、输入幅值/变化率、状态和约束裕量、到达/保持时间、Bellman 残差、参数漂移、数据最小奇异值、计算耗时、触发次数和通信率。采样最小安全余量只是采样证据；只有包含采样间分析或适当事件/界的实验才能进一步讨论区间行为。

论文复现将变体与证据状态分开保存。变体为 `original/refactored/corrected/recalibrated`；记录过的重新调参仍是 recalibration，不能作为原参数复现证据。证据状态至少区分：

| 状态 | 含义 |
|---|---|
| `source_reviewed` | 已读源码，尚未运行 |
| `run_completed` | 所登记变体运行成功，尚未比对原论文 |
| `numerical_match` | 指定指标、场景、容差与参考结果一致；比较对象明确为原论文、缓存参考值，或固定原程序的新运行 |
| `independent_rerun` | 不同干净环境完成相同协议 |

每个状态应关联证据文件与 commit；没有证据就保留未完成状态。未来硬件试验单独登记，不由上述状态自动推出。

## 10. 测试与自动化分层

- **数学与接口层**：梯度有限差分、二次价值交叉项、维度、单位、输入方向、Bellman 恒等式、无效数据拒绝。
- **解析基线层**：CT LQR 与积分 PI，后续 DT LQR/PI/VI；这是检测符号和数据回归约定的第一道检查。
- **数值层**：步长/容差、特征尺度、数据秩、随机流、积分窗口和约束失败。
- **论文复现层**：固定场景重算及指标比较；缓存图或文件 hash 一致只能说明缓存身份，不能代替重算。
- **外部系统层**：Simulink、可选工具箱、外部求解器及之后的 SIL/PIL/HIL 各有独立依赖和结果。

默认快速检查只运行基础 MATLAB 测试与小基线。耗时多种子实验、原论文全量重算和需要专用工具箱的测试分别运行。缺少数据/依赖时标记该层未运行，不能通过宽松 skip 把论文复现层报告为通过。基础框架采用 MATLAB 自带 [matlab.unittest](https://www.mathworks.com/help/matlab/ref/matlab.unittest-package.html)，不要求额外购买 MATLAB Test。

目标基线环境是已检测到的 R2025b；更早版本的兼容性必须实际验证。Deep Learning/Control System/Optimization/Parallel Computing/Simulink 是按模块声明的可选依赖，不作为基础库的统一前提。

## 12. 分阶段推进

### 第一阶段：将规范放到可运行算例上

本包提供原创双积分器 CT on-policy integral PI，使用 `Q=I,R=1,K0=[1,2]`，已知解析参照 `K*=[1,sqrt(3)]`。它用于验证特征、积分 Bellman 数据、回归和记录接口。实际实现与执行结果以 README、VALIDATION 文件为准。

### 第二阶段：你的 FxT 论文完整迁移

固定上游 commit → 保存原实现基线 → 逐项核对特征梯度与 Bellman 量 → 拆分模型、学习律、历史栈、求解器和图表 → 在匹配配置下做旧/新输出比较。源码修正会改变数值结果时，分别保留 `legacy` 与 `corrected` 场景和参数，不能只做一份“美化重构”。

验收：一条明确命令重建指定图和指标，完整轨迹可查，公式映射与差异说明齐全。该阶段是后续最值得投入的工作。

### 第三阶段：方法矩阵扩展

按 CT/DT LQR → nonlinear PI/VI → IRL/off-policy → identifier/CL → constrained/PPC → games 的顺序增加方法；每类至少一个带解析答案或可独立交叉验证的算例，再接入复杂论文案例。Lewis 和 lujingweihh 来源分别登记，不强行共用不兼容的学习假设。

### 第四阶段：机器人和执行约束

增加显式控制采样和零阶保持、扰动/时延/攻击、固定维度 Simulink 接口、离线数据回放。更进一步的代码生成、SIL/PIL/HIL 或硬件部署由具体项目的模型、设备和授权决定。当前规范不预先承诺某算法可以安全上机。

## 13. 维护和版本规则

接口变化采用语义版本；论文结果 pin 精确 commit/版本。影响科学结论的修改（特征导数、代价、学习律、时钟、数据筛选或实际输入）需要新结果版本，不能仅更新图片。

`AGENTS.md` 保留共同约定；新论文的特殊约定放在其复现包中，不污染整个库。关键设计决策简短记录在 `docs/adr/`。第三方依赖固定版本和来源，主库只包含已允许分发的文件。

每次交付分别说清：实现了什么、执行了什么检查、哪个算法/论文仍待完成、下一项验收是什么。一个通过测试的参考算例只证明该算例和相应接口检查通过。


## 14. 查新后的扩展顺序

先完善数值积分、数据/策略一致性、稳定初始化和输出反馈契约，再做CT/DT解析方法与FxT-CL-ACI迁移。Itô随机LQ、平均场社会最优/团队博弈、离线鲁棒优化按研究需求接入。Koopman、学习特征、PINN/PDE、分布回报及CTMC熵方法作为可选后端。

不能把“已考虑接口”写成“已融入算法”。每个方法都必须从全文记录、假设映射、最小对照、实现证据逐步升级状态。详见 registry/algorithms.json 和 templates/method-intake.md。
